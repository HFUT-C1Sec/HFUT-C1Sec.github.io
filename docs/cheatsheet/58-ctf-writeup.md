# 📝 CTF Writeup 规范与复盘方法论

> 对应课程 3.3。Writeup 是 CTF 选手的「作品集 + 学习记录 + 声誉资产」三合一。写好 writeup 的能力 = 复盘的能力 = 进步的速度。

---

## 一、🟢 Writeup 标准结构

```markdown
# 题目名（赛事/分值/方向）

## 题目描述
原始题面 + 附件列表（保留原始信息）

## 解题过程
### 1. 侦察
[做了什么：file/strings/端口/目录扫描……]
### 2. 关键发现
[哪个点让思路突破——最重要的部分]
### 3. 利用
[完整脚本/命令，可复现]
### 4. Flag
flag{...}

## 复盘
[这题考什么知识？我的盲区在哪？下次遇到怎么快速识别？]
```

### 写作三原则

```text
1. 可复现：别人拿你的 writeup 能完整重走一遍（命令+参数+版本）
2. 讲思路不讲流水账："扫了 20 个目录"没有信息量，
   "从 robots.txt 注意到 /backup 提示，才转向备份文件利用"才有
3. 复盘必写：解题过程 30%，复盘 70%——复盘才是进步的部分
```

## 二、🟡 复盘方法论（错在哪→盲区→补什么）

```text
每道未解出/看 writeup 的题，回答四个问题：
1. 卡在哪一步？（识别/利用/脚本/方向）
2. writeup 的关键一步，我为什么没想到？（知识缺失 or 思维定式）
3. 这题背后对应哪个知识点/技巧？（归类到知识库）
4. 下次遇到什么特征能快速想起它？（提炼识别信号）

示例：
「卡在识别。writeup 用了 php://filter 链 RCE，我只知道经典用法。
 盲区：filter chain 可以无 allow_url_include RCE。
 归类：Web→文件包含→filter chain 进阶。
 识别信号：包含点 + allow_url_include 关闭 + PHP≥7.x」
```

### 知识库联动

```text
复盘产物直接进 Obsidian：
  新知识 → 写进对应《XX全技巧》或新建一篇
  新技巧 → 加到对应篇的速查表
  识别信号 → 积累成「特征→考点」映射表
（本知识库就是这么长出来的）
```

## 三、🟡 比赛方法论

### 赛时时间分配（24h 赛制示例）

```text
前 30min：全览题目，按方向+分值预分配人
前 1/3：先打「低分必拿题」（签到/misc/web 入门）保底
中段：主攻各自方向，卡 45min 无进展就换题/求助队友交叉看
最后 2h：全员复盘「差一步」的题（差一步的题性价比最高）
```

### 团队协作

```text
共享发现：所有侦察结果实时记录（玄幕红队协同平台/共享文档）
交叉视角：卡住的题 30 分钟喊人来围观（换脑子比硬磕值钱）
禁止行为：互抢键盘 / 只顾自己方向不看全局 / flag 不共享
```

- 把课程里解过的任意 3 题按标准结构重写 writeup（对照三原则自检）
- 给一道未解题写四问复盘

## 🎓 上课流程卡（3.3a · Writeup 与复盘方法论 · 120 分钟）

> 给讲师：本课在结业周，学员已有大量解题经历——所以这课的形态不是"讲课"是"工作坊"：一半时间学员实际写，一半时间互评。讲师的准备重心在"范例材料"而非知识点。

**教学目标**：下课时每位学员产出①一份符合三原则的完整 writeup（现场写完）②一份四问复盘 ③知道自己的 writeup 差在哪（互评结论）。

**课前准备**：
- 好坏 writeup 对比样例各 1 份（好的可从网上知名战队博客找，坏的可以匿名化往期学员的——注意措辞保护）
- 打印「标准结构模板」+「四问复盘」各一份（每人一张）
- 选定现场写作题：本期模拟赛中一道全班都见过的题（共同记忆，避免现场读题浪费时间）

| 时间 | 环节 | 讲师动作 |
|---|---|---|
| 0-15 | 导入 | 对比展示：同一道题的两份 writeup（一份流水账一份带思路）——"求职时 attach 在简历里的就是这个，写烂了等于白解题" |
| 15-35 | 讲解 | §一 标准结构逐段过 + 写作三原则（可复现/讲思路/复盘占 70%）——每条原则配正反例各一个 |
| 35-45 | 讲解 | §二 四问复盘法：拿一道共同经历的具体题现场演示填四问（示范到"识别信号"这一步的价值） |
| 45-90 | 实操（核心） | 学员现场写：选模拟赛中自己解过的一道题，45 分钟写出完整 writeup。**讲师巡场不看代码看结构**：有没有复盘段、是不是流水账、可复现性（命令全不全） |
| 90-110 | 互评 | 两人互换互评，用三原则打勾清单；讲师抽 2 份投屏点评（一好一改进，先好后坏——保护积极性） |
| 110-120 | 收口 | §三 比赛方法论速过（时间分配+协作）+ 作业：结业赛前把 writeup 集整理成个人 GitHub 仓库（"这就是你们结业时带的简历"） |

**学员常见卡点（预判）**：
1. 写成流水账（"然后我试了…然后我又试了"）→ 教删减法：每段问"读者能学到什么"，学不到就删
2. 复盘写不出 → 四问模板直接照填（这就是为什么发模板）
3. 嫌麻烦不想写 → 招牌话术："你最强的对手 writeup 比你多十倍——面试和招人方看的不是你会多少，是你能证明多少"
4. 命令贴不全（可复现性差）→ 教"假设读者环境为零"标准：版本/路径/参数一个不少

**被问倒的兜底**："writeup 写这么细不怕方法被学走？" → "writeup 的价值恰恰是公开交换——社区里 writeup 质量是你技术声誉的直接凭证，藏着掖着的人进步最慢。安全行业靠声誉流通"。
